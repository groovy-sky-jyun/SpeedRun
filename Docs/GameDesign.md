# SpeedRun — 러너 기획서

> **보관용.** 별도 프로젝트로 이전 예정이다. 현 프로젝트의 기획서는 `GameDesign_Parkour.md`.

폐기물 처리 공장이 플레이어를 "제거 대상"으로 인식한다.
멈출 수 없는 통로를 달리며, 공장이 겨냥해 작동시키는 함정을 파쿠르로 넘긴다.

| 장르 | 시점 | 인원 | 엔진 |
|---|---|---|---|
| 러너 · 파쿠르 액션 (리듬감 + 속도감) | 3인칭 | 1인 | Unreal Engine 5.7 |

---

## 1. 컨셉

### 세계관
무인 자동화 폐기물 처리 공장. 라인에 잘못 떨어진 플레이어를 공장 제어 시스템이 **불량 폐기물**로 분류하고, 처리 절차를 그대로 집행한다.

### 공장이 적(敵)이다
함정은 "그 자리에 놓여 있는 장애물"이 아니라 **공장이 플레이어를 향해 작동시키는 처리 장비**다. 이 차이를 연출로 계속 각인시킨다.

| 연출 | 내용 |
|---|---|
| 조준 | 플레이어가 접근하면 스캐너가 붉게 훑고, 그 직후 함정이 작동 |
| 추적 | 천장 레일 로봇팔이 플레이어 속도에 맞춰 따라오며 집게를 내려찍음 |
| 유도 | 셔터가 직진로를 닫아 플레이어를 원하는 방향으로 몰아넣음 |
| 방송 | 안내 음성이 사무적인 톤으로 처리 단계를 고지 ("이물질 감지. 압축 처리 개시.") |
| 반응 | 파쿠르 성공 시 경보음 톤이 올라가며 다음 함정이 더 빨리 작동 |

플레이어를 쫓는 **압축기 램(못 박힌 벽)** 은 이 컨셉의 중심 장치다. 별도의 몬스터가 아니라 처리 라인의 마지막 공정이며, 라인 끝까지 밀어붙이는 것이 공장의 목적이다.

### 톤 앤 매너
- 감정 없는 기계의 폭력. 위협적이지만 악의는 없고, 사무적이다.
- 색: 산업 경고색(주황·검정 사선) + 구역별 조명 테마.
- 사운드: 프레스 타격, 유압 배기, 컨베이어 회전음이 **곧 BPM**이 된다.

## 2. 코어 루프

```
자동 주행 → 함정 인지(예고 연출) → 정답 입력 판단 → 판정
   ├ 성공 → 콤보 +1 → (콤보 임계치) 부스트 상태 → 압축기와 거리 회복
   └ 실패 → 콤보 초기화 → 압축기 거리 감소
                                    └ 거리 0 → 사망 → 처음부터 재시작
```

한 판의 목표는 **라인 끝(배출구)까지 도달**. 실패 시 스테이지 처음부터 다시 시작한다.

### 플레이어의 실력이란

이 게임에서 실력은 **순간적으로 올바른 동작을 골라내는 판단력**이다. 타이밍 정확도가 아니다.

- 함정 하나에는 **정답이 하나뿐**이다. 여러 방법으로 넘을 수 없다.
- 어려운 것은 "언제 누르나"가 아니라 "무엇을 누르나"다.
- 따라서 함정을 **보고 즉시 식별할 수 있어야** 하며, 식별이 안 되면 판단 게임이 아니라 암기 게임이 된다. (→ 8장 시각 언어)

## 3. 이동 · 조작

플레이어는 조작하지 않아도 전방으로 계속 달린다. 정지 · 후진 · 감속 입력은 없다.

### 입력 4종

플레이어가 고르는 것은 **입력 4종**이고, 실제로 재생되는 몽타주는 지형에 따라 자동 선택된다. 이 둘을 분리한다.

| 키 | 입력 | 의미 |
|---|---|---|
| `Space` | 도약 | 아래에서 솟은 것을 넘는다 |
| `C` | 하강 | 위에서 내려온 것 아래로 몸을 낮춘다 |
| `A` | 좌 회피 | 우측에서 뻗어온 것을 피한다 |
| `D` | 우 회피 | 좌측에서 뻗어온 것을 피한다 |

`W` `S`는 사용하지 않는다. 세로축 입력을 열면 플레이어가 전진 속도를 통제하게 되어 "멈출 수 없다"는 전제가 깨진다.

### 좌우 이동 — Sidestep

`A` `D`는 **판정 입력이자 이동 수단**이다. 키 하나가 두 가지 의미를 갖지 않도록, 좌우 이동을 자유 이동이 아닌 **스텝의 연속**으로 구현한다.

- 한 번 누르면 좌/우로 한 스텝 이동한다. (150 cm, 0.25초)
- 계속 누르고 있으면 스텝이 반복되어 자유 이동처럼 보인다.
- 판정 구간에서 누른 스텝이 곧 회피 판정이다.

레인 스냅은 아니므로 좌우 위치는 여전히 연속값이지만, 회피 동작 자체는 이산적이라 성공·실패가 명확하다.

### 주행 속도 (초안)

| 항목 | 값 |
|---|---|
| 기본 주행 속도 | 900 cm/s |
| 부스트 주행 속도 | 1,150 cm/s |
| Sidestep 이동 거리 | 150 cm |
| Sidestep 소요 시간 | 0.25초 |
| 통로 기본 폭 | 600 cm (스텝 4회로 벽에서 벽) |

## 4. 파쿠르 액션

입력 4종은 축(평지 · 수직)과 무관하게 고정이다. 몽타주만 축별로 한 세트씩 둔다.

| 입력 | 평지 몽타주 | 수직 몽타주 |
|---|---|---|
| `Space` 도약 | **Vault** (허리 높이 넘기) · **Jump** (바닥 틈 건너기) | **ClimbLeap** (끊긴 사다리 도약) |
| `C` 하강 | **Slide** | **WallPress** (벽면 돌출물에 밀착) |
| `A` 좌 회피 | **Sidestep L** | Sidestep L (벽면 좌우) |
| `D` 우 회피 | **Sidestep R** | Sidestep R (벽면 좌우) |

`C`가 두 축 모두 "장애물 안쪽으로 몸을 낮춘다"는 같은 개념이라, 플레이어가 새로 배울 것이 없다.

### 보류 · 제외

| 액션 | 처리 | 이유 |
|---|---|---|
| Mantle | **보류** | 올라선 뒤 속도가 크게 죽어 성공인데 손해로 느껴진다. 통로에 높이차 구간을 실제로 넣기로 확정되면 추가 |
| Duck | **제외** | Slide와 판단상 같은 문제("낮게 지나가라")다. 정답이 1개여야 하는데 선택지가 둘이면 모호해진다 |
| Hang (상태) | **전환** | 멈춰서 매달리는 상태는 즉사와 같다. `CUSTOM_Hang` 이동 모드를 없애고, ClimbLeap 몽타주의 **경유점**으로 재사용한다 |
| 사다리 · 수직 덕트 (수동 등반) | **전환** | 자동 등반 + 축 전환으로 대체 (→ 7장) |
| 컨베이어 역주행 | **제외** | `W` 유지가 필요해 오토런과 충돌 |

## 5. 판정 — 반응 윈도우

실력 축이 타이밍이 아니라 판단이므로 **±윈도우(타이밍 윈도우)를 쓰지 않는다.** 일찍 눌렀다고 벌점을 주면 정답을 빨리 알아챈 플레이어가 손해를 보게 되어 의도와 정반대가 된다.

대신 **반응 윈도우**를 쓴다. 함정이 보인 뒤부터 도달 시각까지가 판정 구간이고, 그 안에서는 언제 눌러도 성공이다. 측정하는 것은 정확도가 아니라 **얼마나 빨리 알아챘는가**다.

```
   인지 지점                          도달 시각
      │◄────── 판정 구간 (성공) ──────►│
──────┴────────────────────────────────┴──────→ 진행
   함정이 보이기 시작            여기까지 안 누르면 Miss
```

### 판정 설계 원칙

실력이 실제로 반영되려면 판정이 세 가지를 지켜야 한다.

| 원칙 | 내용 |
|---|---|
| **결정론성** | 같은 상황 · 같은 입력이면 항상 같은 결과. 판정은 프레임이 아닌 **시간(초)** 기준으로 계산하고, 함정 작동 타이밍에 난수를 넣지 않는다. 같은 프레임에 두 입력이 들어오면 **나중 입력을 우선**한다 (마음을 바꾼 것으로 해석) |
| **판독 가능한 실패** | 왜 실패했는지 즉시 보여야 반복이 학습이 된다. 오답 시 잘못된 동작을 실제로 수행시키고, 사망 화면에 직전 실패 3건을 정답과 함께 표시한다 |
| **열린 상한** | 잘하는 플레이어가 더 잘할 여지가 있어야 한다. 판정은 이산이되 **성과는 연속값**으로 둔다 |

### 판정 결과 3종

| 결과 | 조건 | 콤보 | 압축기 거리 | 연출 |
|---|---|---|---|---|
| **Success** | 판정 구간 안에서 정답 입력 | +1 | +40 ~ +100 cm (반응 속도 비례) | 동작 성공, 속도 유지 |
| **Wrong** | 판정 구간 안에서 오답 입력 | 0으로 초기화 | −400 cm | **잘못된 동작을 실제로 수행하다** 피격 + 경직 0.6초 |
| **Miss** | 무입력으로 도달 시각 경과 | 0으로 초기화 | −400 cm | 피격 모션 + 감속 |

Perfect / Good 등급은 두지 않는다. 타이밍이 실력 축이 아니므로 등급을 나눌 근거가 없다.

오답일 때 **캐릭터가 잘못된 동작을 실제로 수행하게** 하는 것이 중요하다. 슬라이드해야 하는데 점프했으면 점프하다가 프레스에 맞아야 왜 틀렸는지 보인다.

### 성과 지표 — 판정은 이산, 보상은 연속

성과는 등급이 아니라 **반응 속도**로 잰다. 인지 지점을 지난 뒤 입력까지 걸린 시간이며, 빠를수록 좋은 단조 증가 지표다.

이때 성과를 이산 등급으로 나누면 0.15초에 반응한 플레이어와 0.39초에 반응한 플레이어가 같은 보상을 받아 **실력 상한이 닫힌다.** 따라서 거리 회복량은 연속값으로 둔다.

```
거리 회복량 = 40 + 60 × (1 − 반응 시간 ÷ 판정 구간 길이)
```

| 반응 시간 | 회복량 |
|---|---|
| 0.1초 | +97 cm |
| 0.5초 | +85 cm |
| 0.9초 | +73 cm |

*(판정 구간 2.0초 기준)*

콤보는 이산(+1)으로 둔다. "끊기지 않았다"는 이진 정보라 연속값으로 만들 이유가 없다.

### 수치 (초안)

| 항목 | 값 |
|---|---|
| 인지 지점 | 도달 2.0초 전 (구역이 올라갈수록 1.2초까지 단축) |
| **인지 시간 하한** | **0.8초 (클램프)** |
| 판정 구간 | 인지 지점 ~ 도달 시각 |
| 입력 버퍼 | 0.15초 (판정 구간이 열리기 전 입력을 보관했다가 열리는 순간 소비) |

입력 버퍼가 있어야 "빨리 알아채고 눌렀는데 무시됨"이 생기지 않는다. 반응 게임에서 이건 치명적이다.

**인지 시간 하한 0.8초의 근거**: 4지선다 선택 반응 시간의 인간 하한이 약 0.45초이고, 입력이 동작으로 성립하는 데 0.15초가 더 든다. 여유를 포함하면 0.8초 아래로는 반응이 물리적으로 불가능하다.

인지 지점을 거리로 배치하면 속도가 오를수록 남는 시간이 줄어든다. 부스트 II(1.28배)에서 1.2초 배치는 실제로 0.94초가 되므로, **최종 인지 시간에 0.8초 하한을 클램프**한다. 그러지 않으면 부스트가 실력 보상이 아니라 반응 불가능 구간이 된다.

### 구현 구조

```
ObstacleQueue ──(다음 함정)──> 예고 연출
      │
      ▼
InputBuffer ──(입력)──> ParkourJudge ──> Success / Wrong / Miss
                             │
                 ┌───────────┴───────────┐
                 ▼                       ▼
        ParkourExecutor            RunState
        (스캔 → Chooser →         (콤보 · 부스트 ·
         몽타주 · Warping)          압축기 거리)
```

| 요소 | 역할 |
|---|---|
| `AObstacle` | 정답 입력 · 판정 구간 · 인지 지점 · 실패 반응을 **직접 선언**한다. 지형을 스캔해 추론하지 않는다 |
| `ObstacleQueue` | 전방 감지 거리 안의 함정을 통과 순서대로 담고, 입력을 **맨 앞 함정에만** 전달한다 |
| `InputBuffer` | 이른 입력을 0.15초 보관한다 |
| `ParkourJudge` | Success / Wrong / Miss만 판정한다 |
| `ParkourExecutor` | 판정 결과를 **어떻게 보여줄지만** 담당한다. 무엇을 할지 결정할 권한은 없다 |

기존 프로젝트의 환경 스캔 · Chooser · Motion Warping은 **판정에서 빼고 연출 전용으로** 역할을 바꿔 그대로 재사용한다. 판정과 연출의 분리가 핵심이다.

함정 하나는 큐에서 한 번만 소비되므로 **연타 방지가 구조적으로 해결**된다.

## 6. 압축기 램 (추격 벽)

라인 뒤쪽에서 못이 박힌 압축 램이 따라온다. 플레이어의 남은 생존력이 곧 **거리**다.

| 항목 | 값 |
|---|---|
| 시작 거리 | 1,200 cm |
| 최대 거리 | 1,600 cm |
| 사망 거리 | 0 cm |
| 상시 접근 속도 | 40 cm/s (지속 압박) |
| Wrong · Miss 페널티 | −400 cm |
| Success 회복 | +40 ~ +100 cm (반응 속도에 비례) |
| 부스트 중 회복 | +150 cm/s |

### 연출
- 거리에 따라 화면 가장자리 붉은 비네트와 램의 유압음 볼륨이 커진다.
- 400 cm 이내부터 못 그림자가 플레이어 발밑까지 드리운다.
- 카메라를 뒤로 돌리지 않아도 위험도를 알 수 있도록 **소리와 화면 효과만으로** 전달한다.
- 수직 구간에서는 같은 압축판이 **아래에서 밀어 올라온다.** 축이 꺾이면 추격자도 같이 꺾일 뿐, 설정이 추가되지 않는다.

## 7. 맵 디자인

### 구성 규칙
- 상하좌우가 폐쇄된 **통로**다. (갈림길이 없으므로 미로는 아니다 — 플레이어에게 "미로"라는 단어를 쓰지 않는다)
- 통로는 **좌회전 · 우회전 · 직진** 세 가지로만 이어진다.
- 통로 기본 폭 600 cm. 커브 구간은 자동 선회하고, 플레이어는 좌우 위치 조정만 한다.
- 좌우 회피 함정의 **안전 구역은 1스텝(150 cm) 이상** 확보한다. 한 번의 스텝으로 확실히 벗어날 수 있어야 한다.
- 폭이 좁아지는 구간에는 회피 함정 없이 **도약 · 하강 함정만** 배치한다.

### 축 전환 (수직 구간)

통로가 위로 꺾이면 **카메라를 회전시켜 위쪽이 곧 전방이 되게** 한다. 플레이어 입장에서는 여전히 앞으로 달리는 것이고, 월드 기준으로만 방향이 90도 꺾인다. 좌회전 · 우회전과 같은 층위의 이벤트로 다룬다.

| 규칙 | 내용 |
|---|---|
| 등반 | **자동**이다. 플레이어는 좌우와 파쿠르만 담당한다 |
| 속도 | 평지와 동일하게 유지해 리듬이 끊기지 않게 한다 |
| 전환 구간 | 카메라 회전 0.4~0.6초 동안 **함정을 배치하지 않는다.** 화면이 도는 중에 판단을 요구하면 실력이 아니라 운이 된다 |
| 추격자 | 압축판이 아래에서 밀어 올라온다 |
| 좌우 | 샤프트도 폭이 있으므로 Sidestep이 그대로 작동한다 |
| 빈도 | **구역당 1회**, 구역 전환점에 배치한다 |

수직 구간을 구역 전환점에 두면 조명 테마와 BPM이 바뀌는 지점을 자연스럽게 덮어준다. "층을 올라간다"는 진행감도 함께 생긴다.

### 구역 테마

| 구역 | 조명 | 주요 함정 | 리듬 |
|---|---|---|---|
| 1. 반입 · 분류 | 주황, 먼지 | 컨베이어, 낙하 컨테이너, 분류 셔터 | 느림 (BPM 110) |
| 2. 소각 · 용해 | 적색, 열기 | 화염 노즐, 용융물 웅덩이, 가열 그레이팅 | 중간 (BPM 128) |
| 3. 냉각 · 세척 | 청색, 수증기 | 고압 분사, 얼어붙은 바닥, 회전 브러시 | 빠름 (BPM 140) |
| 4. 압착 · 배출 | 무채색, 저조도 | 프레스 연속, 절단 레이저, 로봇팔 | 최고 (BPM 150) |

색과 소음이 구역마다 완전히 달라지므로, 단조로운 공장 비주얼 문제를 구역 전환으로 해소한다.

## 8. 함정 · 지형지물

### 시각 언어 (시스템의 일부)

정답이 하나인 판단 게임에서 재미는 **함정 식별**에서 나온다. 이것이 무너지면 판단 게임이 암기 게임으로 전락한다. 따라서 시각 언어는 아트 가이드가 아니라 **데이터 애셋으로 강제**한다.

| 정답 | 실루엣 | 색 |
|---|---|---|
| `Space` 도약 | 아래에서 위로 솟음 | 주황 |
| `C` 하강 | 위에서 아래로 내려옴 | 노랑 |
| `A` 좌 회피 | 우측 벽에서 뻗어나옴 | 적색 |
| `D` 우 회피 | 좌측 벽에서 뻗어나옴 | 적색 |

처음 보는 함정도 **형태만 보고 정답을 알 수 있어야** 판단 실력이 성립한다. 신규 함정 제작 시 이 매핑을 벗어나지 못하게 막는다.

### 평지 함정

| 이름 | 작동 | 정답 |
|---|---|---|
| 파이프 다발 | 허리 높이 정적 장애물 | `Space` (Vault) |
| 끊긴 발판 | 바닥이 사라진 구간 | `Space` (Jump) |
| 하부 절단 레이저 | 무릎 높이 가로선이 훑음 | `Space` |
| 프레스 | 천장에서 주기적으로 내려찍음 | `C` (Slide) |
| 낮은 덕트 | 통로를 가로지르는 배관 | `C` |
| 상부 절단 레이저 | 가슴 높이 가로선이 훑음 | `C` |
| 로봇팔 | 플레이어 좌우 위치를 조준해 내려찍음 | `A` / `D` (반대쪽) |
| 화염 노즐 | 한쪽 벽면에서 측면 분사 | `A` / `D` (반대쪽) |
| 낙하 컨테이너 | 예고된 착탄 범위에 낙하 | `A` / `D` |

절단 레이저 상 · 하 한 쌍은 **겉모습이 비슷한데 정답이 반대**인 조합이다. 색(주황/노랑)으로만 구분되므로 식별 난이도를 올리는 데 쓴다.

### 수직 함정

| 이름 | 작동 | 정답 |
|---|---|---|
| 끊긴 사다리 | 등반 레일이 중간에 끊김 | `Space` (ClimbLeap) |
| 벽면 돌출 설비 | 배관 · 밸브가 진행 방향으로 튀어나옴 | `C` (WallPress) |
| 하강 집게 | 위에서 좌우 위치를 조준해 내려옴 | `A` / `D` |

### 배치 규칙
- 함정 간격은 해당 구역 BPM의 **비트 배수**로 스냅한다. (4비트 · 2비트 · 1비트)
- 같은 정답 입력이 3회 이상 연속되지 않게 섞는다.
- 신규 함정은 반드시 **안전한 1회 학습 구간**에서 먼저 등장시킨다.
- 판정 구간이 겹치지 않도록 최소 간격을 지킨다. (에디터 툴에서 자동 검증)

### 난이도 설계 축

정답이 하나이고 판단이 실력이므로, 난이도는 **판단 시간과 식별 난이도**에서 나온다. 장애물 크기가 아니다.

| 축 | 방법 |
|---|---|
| 판단 시간 압축 | 커브 뒤 배치, 조명 축소, 속도 상승 → 인지 지점이 짧아짐 |
| 식별 난이도 | 겉모습이 비슷한데 정답이 다른 함정 쌍 (상 · 하부 절단 레이저) |
| 연속 배치 | 이전 동작 실행 중에 다음 판단이 시작되게 |
| 오답 유도 | 직전 함정과 반대 입력을 요구하는 배치 |

부스트가 여기에 자연스럽게 맞물린다. 속도가 오르면 인지 지점부터 도달까지의 **시간이 줄어들어** 난이도가 저절로 올라간다. 별도 장치가 필요 없다.

## 9. 콤보 · 부스트

파쿠르를 연속 성공하면 부스트 상태에 진입한다. (기존 `대시`는 순간 가속을 뜻하므로, 지속 상태인 이 시스템은 **부스트**로 명명)

| 콤보 | 상태 | 효과 |
|---|---|---|
| 0–4 | 기본 | — |
| 5–9 | 부스트 I | 속도 1.15배, 거리 회복 +100 cm/s |
| 10+ | 부스트 II | 속도 1.28배, 거리 회복 +150 cm/s, 화면 왜곡 · 잔상 |

- 부스트 중에는 함정 작동 주기도 빨라져 **난이도가 같이 오른다.** 보상이자 리스크.
- Wrong · Miss 1회로 콤보와 부스트가 모두 초기화된다.

## 10. 리듬 설계

리듬 게임은 아니지만 **리듬감**이 핵심 감각이다.

- 모든 함정의 작동 타이밍을 구역 BPM 그리드에 정렬한다.
- BGM은 공장 소음(프레스, 유압, 컨베이어)을 악기로 쓴 인더스트리얼 트랙.
- 파쿠르 성공 시 타격음이 비트 위에 얹히고, 콤보가 쌓일수록 레이어가 추가된다.
- 실패 시 트랙 레이어가 벗겨지며 소리가 얇아진다 — 실패를 청각으로 즉시 인지시킨다.

> **주의**: 여기서 리듬은 **감각**이지 판정 기준이 아니다. "비트에 맞춰 눌러야 성공"하는 리듬 게임 판정은 반응 윈도우와 배타적이다 — 전자는 정확한 순간을, 후자는 빠른 판단을 요구한다. 둘을 동시에 만족시킬 수 없으므로 리듬 판정 도입은 이 기획의 범위 밖으로 둔다.

## 11. 사망 · 재시작

- 압축기 거리 0 → 즉시 사망 연출(램에 밀려 압착) → 스테이지 처음부터.
- 재시작은 **1초 이내**. 로딩 없이 즉시 리스폰해 재도전 리듬을 끊지 않는다.
- 사망 화면에 최고 도달 거리 · 최대 콤보를 표시해 다음 시도의 목표를 준다.
- 함께 **직전 실패 3건**을 정답과 나란히 표시한다. (`프레스 — 도약 입력 (정답: 하강)`) 실패 원인이 보여야 반복이 학습이 된다.

## 12. UI

| 요소 | 위치 | 내용 |
|---|---|---|
| 압축기 거리 게이지 | 화면 하단 | 플레이어–램 거리. 위험 구간에서 붉게 명멸 |
| 콤보 카운터 | 좌측 상단 | 현재 콤보 · 부스트 단계 |
| 판정 표시 | 화면 중앙 하단 | Success / Wrong / Miss |
| 진행도 | 상단 | 구역 이름 · 라인 진행률 |

HUD는 최소화한다. 위험도와 콤보는 가급적 **화면 효과와 사운드로** 전달하고, 게이지는 보조 수단으로 둔다.

함정 예고는 HUD 아이콘이 아니라 **함정 자체의 실루엣과 색**으로 한다. 아이콘으로 정답을 알려주면 식별이라는 핵심 재미가 사라진다.

## 13. 기존 프로젝트에서의 변경점

| 항목 | 기존 | 변경 |
|---|---|---|
| 이동 | `W` `A` `S` `D` 자유 이동 | 자동 전진 + `A` `D` Sidestep |
| 카메라 | 마우스 자유 시점 | 고정 추적 카메라 + 축 전환 시 스크립트 회전 |
| 파쿠르 선택 | `Space` 단일 키로 전 액션 | 입력 4종 (도약 · 하강 · 좌 · 우) |
| 정답 결정 | 환경 스캔 → 점수 추론 | `AObstacle`이 직접 선언 |
| 환경 스캔 | 판정 + 연출 | **연출 전용** (몽타주 선택) |
| 실패 조건 | 없음 (안 누르면 일반 점프) | Wrong · Miss |
| 난이도 축 | 장애물 크기 | 판단 시간 + 식별 난이도 |
| Hang | 이동 모드(상태) | ClimbLeap 몽타주의 경유점 |
| 대시 | `Q` 수동 대시 | 콤보 누적 시 자동 진입하는 부스트 상태 |
| 레벨 | 자유 배치 파쿠르 블록 | BPM 그리드에 스냅된 통로 세그먼트 |

**재사용**: 환경 스캔 · Chooser 애니메이션 선택 · Motion Warping · Hang 이동 로직은 **연출 계층으로 이동**해 그대로 활용한다.

## 14. 개발 우선순위

1. 자동 주행 + Sidestep + 고정 추적 카메라
2. 압축기 램 추격 · 거리 시스템 · 사망 / 재시작
3. `AObstacle` · `ObstacleQueue` · `InputBuffer` · `ParkourJudge` (판정 계층)
4. 입력 4종 ↔ 몽타주 연결 (기존 스캔 · Chooser를 `ParkourExecutor`로 이관)
5. 평지 함정 4종(파이프 · 프레스 · 로봇팔 · 끊긴 발판)으로 1구역 프로토타입
6. 콤보 · 부스트
7. 축 전환(수직 구간) + 수직 함정 3종
8. BPM 그리드 배치 툴 · 사운드 레이어
9. 구역 4개 확장 · 연출 강화
