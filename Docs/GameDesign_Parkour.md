# SpeedRun — 파쿠르 타임어택 기획서

> 현 프로젝트의 기획서. 기존에 구현된 파쿠르 구조(환경 스캔 · 액션 점수 평가 · Motion Warping · Chooser)를 그대로 살리는 방향이다.
> `GameDesign.md`(러너 기획)는 별도 프로젝트로 이전 예정.

짧은 코스를 최단 시간에 주파한다. 같은 지형을 어떤 액션으로 넘느냐가 곧 기록 차이가 된다.

| 장르 | 시점 | 인원 | 엔진 |
|---|---|---|---|
| 3인칭 파쿠르 타임어택 | 3인칭 자유 시점 | 1인 | Unreal Engine 5.7 |

---

## 1. 핵심 재미

**액션 선택이 곧 전략이다.**

같은 컨테이너 벽을 Vault로 넘느냐, Mantle로 올라서느냐, Hang으로 돌아가느냐에 따라 시간이 달라진다. 그리고 플레이어는 이것을 메뉴로 고르지 않고 **접근 속도와 각도로 간접 제어**한다.

> 빠르게 정면으로 들어가면 Vault, 느리게 붙으면 Mantle, 측면에서 붙으면 Hang.

숙련될수록 "어떻게 진입해야 원하는 액션이 나오는지"를 알게 되고, 그것이 곧 실력이다. 환경 스캔과 액션 점수 평가가 구현 방식이 아니라 **게임 메커닉 그 자체**가 된다.

---

## 2. 코어 루프

```
코스 진입 → 주행 · 파쿠르 → 완주 시간 기록
   ├ 더 빠른 루트를 찾는다 → 재도전
   └ 낙하 · 실수 → 체크포인트 복귀 (시간은 계속 흐름) → 재도전
```

패배 조건이 없다. **유일한 페널티는 시간**이다. 즉사와 리셋 대신 "느려졌다"로만 처벌해 재도전 부담을 없앤다.

---

## 3. 조작

기존 조작을 그대로 쓴다.

| 키 | 동작 |
|---|---|
| `W` `A` `S` `D` | 자유 이동 |
| 마우스 | 자유 시점 |
| `Space` | **파쿠르 (문맥에 따라 액션 자동 선택)** |
| `Shift` | 전력 질주 |
| `R` | 즉시 리스타트 |

`Space` 하나로 모든 파쿠르를 처리하는 것이 이 게임의 정체성이다. 플레이어가 액션을 고르는 것이 아니라 **몸이 지형에 반응한다.**

---

## 4. 파쿠르 액션과 속도 손실

**속도 손실 차등이 이 기획의 엔진이다.** 액션마다 잃는 속도가 다르기 때문에 루트 선택이 성립한다.

| 액션 | 대응 지형 | 완료 후 속도 | 성격 |
|---|---|---|---|
| **Jump** | 바닥 틈 | 100% | 손실 없음 |
| **Vault** | 허리 높이 (50~150 cm), 얇은 것 | 90% | 빠르지만 진입 속도가 필요 |
| **Mantle** | 가슴 높이 이상 | 40% | 어디서든 되지만 느리다 |
| **Hang → Shimmy → Climb** | 매달릴 수 있는 모서리 | 10% | 거의 정지. 다른 방법이 없을 때의 최후 수단 |

Hang이 느린 것은 단점이 아니라 **"느리지만 확실한 선택지"** 로서 루트 트리를 만든다.

### 액션 선택 규칙

기존 `Evaluate()` 점수 평가를 그대로 쓰되, **진입 속도를 점수에 반영**한다.

- Vault는 진입 속도가 일정 이상일 때만 높은 점수를 받는다.
- Mantle은 속도와 무관하게 항상 중간 점수를 받는다. (안전한 대안)
- Hang은 위 둘이 불가능할 때만 선택된다.

이 규칙 하나로 "빠르게 붙으면 빠른 액션이 나온다"는 감각이 생긴다.

---

## 5. 루트 설계

### 핵심 규칙

> **모든 장애물은 최소 2가지 대응이 가능해야 한다. 하나는 빠르고 어렵고, 하나는 느리고 안전하다.**

이 규칙을 지키지 않으면 정답이 하나로 고정되어 루트 최적화가 사라진다.

| 예시 지형 | 빠른 길 | 안전한 길 |
|---|---|---|
| 가슴 높이 컨테이너 | 전력 질주 후 Vault (90%) | Mantle (40%) |
| 3 m 간격 옥상 | 도움닫기 후 Jump (100%) | 아래 배관으로 우회 |
| 높은 벽 | 옆 상자를 밟고 2단 Vault | Hang → Shimmy → Climb (10%) |

### 배치 원칙
- 빠른 길은 **실패 시 손해가 크다.** (낙하 → 체크포인트)
- 안전한 길은 항상 존재한다. 막히는 구간을 만들지 않는다.
- 갈림길은 **눈으로 보여야 한다.** 숨겨진 지름길은 암기 게임을 만든다.

## 6. 코스 구성

| 코스 | 목표 시간 | 성격 |
|---|---|---|
| 1. 학습 | 30초 | 각 액션을 1회씩 강제로 사용. 갈림길 없음 |
| 2. 본선 | 60초 | 갈림길 3곳. 루트 조합이 기록을 좌우 |
| 3. 고난도 | 45초 | 지름길이 좁고 실패 손해가 크다 |

무대는 **공사 중인 도시 옥상**. 컨테이너 · 배관 · 비계 · 철골이면 필요한 높이 변화가 전부 나오고, 에셋 수급도 쉽다.

---

## 7. 시간 · 기록

| 요소 | 내용 |
|---|---|
| 타이머 | 시작선 통과 시 시작, 결승선 통과 시 정지 |
| 체크포인트 | 낙하 시 복귀. **시간은 멈추지 않는다** |
| 개인 최고 기록 | 코스별 저장 |
| 고스트 | 최고 기록 주행을 반투명 캐릭터로 동시 재생 |
| 즉시 리스타트 | `R`로 0.5초 내 재시작 |

고스트는 위치 · 회전을 0.1초 간격으로 기록해 재생하는 정도면 충분하다.

---

## 8. UI

| 요소 | 위치 | 내용 |
|---|---|---|
| 타이머 | 상단 중앙 | 현재 시간 · 최고 기록과의 차이(±) |
| 체크포인트 알림 | 화면 중앙 | 통과 시 구간 기록 표시 |
| 속도계 | 우측 하단 | 현재 속도 (속도 유지 감각을 시각화) |

HUD는 이 세 개면 충분하다. 속도계는 "지금 액션이 속도를 얼마나 깎았는지"를 플레이어가 체감하게 만드는 장치라 반드시 넣는다.

## 9. 기존 코드 활용

| 자산 | 상태 |
|---|---|
| `UParkourComponent` (스캔 · 점수 평가) | **그대로 사용** |
| `UParkourActionBase` + Vault · Mantle · Hang | **그대로 사용** |
| `UParkourMovementComponent` (`CUSTOM_Hang`) | **그대로 사용** |
| Chooser Table · Motion Warping | **그대로 사용** |
| `AN_SetMovementMode` · `AnimNotifyState_ParkourPhysics` | **그대로 사용** |
| `AParkourBlock` | 코스 지형 블록으로 확장 |

### 추가 구현

1. **액션별 속도 손실** — `ExecuteAction()` 종료 시 속도 배율 적용
2. **진입 속도 기반 점수 보정** — `Evaluate()`에 `CurrentSpeed` 가중치 추가
3. 타이머 · 체크포인트 · 결승선
4. 고스트 기록 · 재생
5. 속도계 HUD
6. 코스 3개 레벨 제작

---

## 10. 개발 우선순위

1. 액션별 속도 손실 + 진입 속도 점수 보정 (**핵심 재미가 여기서 나온다**)
2. 타이머 · 체크포인트 · 즉시 리스타트
3. 학습 코스 제작 → 액션 4종이 의도대로 선택되는지 검증
4. 속도계 HUD
5. 본선 코스 제작 (갈림길 3곳)
6. 개인 최고 기록 저장 · 고스트
7. 고난도 코스 · 연출 보강

1번이 끝나는 시점에 이 게임이 재밌는지 판가름 난다. 코스 제작보다 먼저 한다.
